# 标注编辑与写回

本指南同时适用于 Web 和移动端。最终单 HTML 只内嵌标注展示能力；编辑器由本地审阅服务临时注入，避免把产品经理不需要的编辑代码交付给阅读者。两端共用一套编辑界面和交互，仅由平台适配层识别业务根节点、页面、Tab 和最高弹层作用域。

## 进入编辑模式

用户提出“编辑标注”“进入编辑模式”“进入标注编辑模式”“我要编辑标注”或同义请求时，从当前 skill 目录直接启动，不要只回复操作命令：

```powershell
node scripts/prototype-annotation-review.mjs serve "目标原型.html"
```

`--port` 仅用于指定首选端口，不区分 Web 或移动端，也不是固定要求。默认或指定端口被占用时，服务自动顺延选择新的可用端口；必须使用命令实际输出的 `editUrl`，不能自行拼接 8090、8899 等端口。

服务输出稳定编辑地址后用浏览器打开。进程存活期间地址持续有效；AI 写回 HTML 后，已打开页面自动刷新到新会话，不要求用户重新打开链接。

每个 HTML 使用 `prototypeId + HTML 绝对路径哈希` 生成唯一目录：

```text
原型所在目录/.prototype-review/{prototypeKey}/
  manifest.json
  sessions/{sessionId}.json
```

每轮编辑使用独立 `sessionId`，不得复用其他 HTML 或上一轮已应用会话。服务只创建和更新上述审阅数据，不依赖 File System Access API（文件系统访问接口）。

## 编辑工作台

- 固定三栏：左侧原型说明、中间原型画布、右侧标注编辑；不提供浮动标注模式。
- 左右栏均可拖拽调宽和向外收起；原型说明允许拉宽到工作区可用宽度上限。
- 编辑工作台只能挂载到当前平台已有的标注顶层：Web 使用 `#prototypeAnnotationRoot`，移动端使用 `#prototypeAnnotationRoot`。禁止在同一页面再创建第二个 `popover` / top layer（浏览器顶层），否则编辑弹窗会被另一顶层截获点击；只有宿主缺失时才允许挂载到 `body` 兜底。
- 原型说明在左栏直接新增栏目、删除栏目和编辑正文；栏目名与正文标题必须来自同一个 `title` 字段。
- 右栏可切换“当前页面 / 全部页面”，显示数量，并按页面、Tab 或最高弹层作用域分组；组名必须取业务页面、Tab、Bottom Sheet、抽屉和弹窗的可见标题；缺少可见标题时将 camelCase 内部名转换为中文业务名或仅显示弹层类型，不能暴露 `page:*`、`sheet:*`、`orderDetail` 等技术 scope。
- 标注卡片显示标题和正文摘要；“原有 / 新增 / 已修改 / 已删除”只用颜色和图例表达编辑状态，不能替代正文摘要。
- 新增标注先锁定当前页面或最高弹层 scope，再由用户点击业务目标；目标和坐标同时保存，禁止落到切换后的其他页面。
- 进入选点状态后，已有标注圆点必须临时禁用 `pointer-events`，避免旧圆点截获点击并把新标注保存到错误目标；取消或完成选点后恢复。
- 新增标注 ID 必须同时校验当前原型全部标注与本轮编辑项，使用时间戳、会话内递增序号和随机值生成，不得因连续点击覆盖上一条新增标注。
- 单击标注点必须直接打开编辑弹窗；只有指针移动超过 `8px` 才进入拖动并记录坐标变更，避免手部轻微抖动吞掉第一次单击。同一标注无论修改多少次，本轮只计 1 项。
- Web 固定画布在窗口变化、左右栏调宽或收起后必须立即重新按实际中间画布等比居中；允许因固定比例出现对称留白，但不得出现上、下留白明显不均的过期布局。
- 本轮新增后又删除的标注直接移除，不记录“已删除”；原有标注删除才保留删除状态供写回。
- 富文本使用单一 `contenteditable` 编辑区，支持正文、标题、粗体、斜体、删除线、列表、引用、链接、表格、代码块、图片和 Mermaid；标题切回正文时必须替换块级元素，不能生成 `h2 > p` 等非法嵌套；弹窗点击空白处不关闭。
- “AI 润色”是每条标注独立选项，位于底部操作区；选择后由 AI 结合需求材料补全该条业务规则，不作为全局开关。

页面、Tab、Bottom Sheet、抽屉或弹窗切换，以及入场/退出动画期间，编辑器必须持续重新识别当前 scope 并重算圆点至少 `900ms`。用户不应通过点击右侧卡片才能让圆点出现。

“全部页面”中的标注必须可跨作用域定位。Web 的页面导航、系统页签和弹层入口使用 `data-proto-route="对应 scope"`，移动端的页面导航、Tab、Bottom Sheet、抽屉和弹窗入口使用 `data-proto-route="对应 scope"`。兼容旧原型时可识别 `[data-page-link]`、`[data-page]`、全局 `navigate/showPage`、`aria-controls`、`data-target` 和常见弹层按钮；新生成原型不得依赖推断。

## AI 应用修改

用户回到对话说“修改标注”“应用本轮标注修改”或同义请求后：

1. 读取对应 `manifest.json` 的 `activeSessionId`，确认 HTML 路径和 `prototypeKey` 匹配。
2. 读取该 session JSON；逐条处理 `_contentPolicy: "ai-polish"` 的标注，把结果写入 `_aiContent` 和 `_aiFormat`，不得改写选择“直接采用”的内容。
3. 执行：

```powershell
node scripts/prototype-annotation-review.mjs apply "目标原型.html" --session "sessionId"
```

4. 写回过程必须同时刷新完整标注展示框架。Web 旧版无区块标记框架只允许通过注入器的 `--migrate-legacy` 受控迁移；保留标注 JSON，移除旧壳和旧运行时，最终只保留一套标准运行时。
5. 生成阶段的标注质量要求仍为 `pass`。编辑回写允许保留用户造成的 `warning`，但 `fail` 仍阻止写回并恢复原 HTML；不得丢弃用户内容。
6. 写回成功后保持本地服务运行，页面自动刷新为新的空白编辑会话；原地址继续有效，状态计数归零，不要求用户刷新或重新打开链接。
7. `apply` 会自动执行注入器质量门禁和 `audit-single-html.mjs`，并输出 `verificationPlan`。AI 只执行计划中实际列出的浏览器检查；`browserChecks` 为空时直接结束，不得为了“再确认一次”自行打开页面。

### AI 写回后的验证分级

- `automatic-only`：本轮没有变化，或仅修改标注标题/正文、AI 润色内容、原型说明栏目与正文；自动审计和结构化数据核对通过后结束，不打开浏览器复查。
- `incremental`：新增、删除、拖动标注，或修改 target、scope、scroll 等定位信息；只打开 `affectedScopes`，不复查未改页面。
- 注入器刷新展示框架只负责保持标准代码最新，不构成额外验证理由；不得仅因框架版本或签名变化扩大检查范围。
- 自动审计失败、受影响 scope 不可达时停止交付；只有用户明确要求全面检查时才遍历其他页面。

## 验收

- 只交付 `serve` 命令输出的完整 `editUrl`，不得把静态预览地址称为编辑地址；打开后必须存在 `proto-editor-edit-mode`、共享三栏、当前/全部页面和新增标注入口。
- Web 与移动端编辑界面、按钮、栏目编辑、当前/全部页面切换和状态计数一致。
- 编辑器根节点的 `data-proto-editor-runtime-status` 必须为 `ready`；不得存在第二个编辑工作台或第二个浏览器顶层。
- 启动编辑服务时，确认地址可访问且状态为 `ready` 后即可交付，不自动演练增删改或多页面跳转。
- 常规编辑写回只按 `verificationPlan.browserChecks` 执行；内容和原型说明修改不打开浏览器，位置、目标或 scope 修改才检查对应页面的列表、圆点和定位。
- 写回后最终 HTML 仍只有一套对应平台展示框架，右下角“注”或移动端三栏/手机入口正常。
- 自动审计失败、受影响 scope 不可达，或抽查发现框架级问题时，立即停止“增量通过”结论并升级完整验证。
